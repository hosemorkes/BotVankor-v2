### 3. Настройка переменных окружения

1. Скопируйте `.env.example` в `.env`:
```bash
# Windows (PowerShell)
Copy-Item .env.example .env

# Linux/Mac
cp .env.example .env
```

2. Откройте `.env` и заполните токены:
```
TELEGRAM_BOT_TOKEN=ваш_токен_бота_здесь
WEATHER_API_KEY=ваш_api_ключ_погоды_здесь

# Координаты Ванкорского месторождения (опционально, есть значения по умолчанию)
VANKOR_LATITUDE=69.5
VANKOR_LONGITUDE=88.0
VANKOR_NAME=Ванкорское месторождение

# Координаты Игарки (для анализа вероятности вылета, опционально)
IGARKA_LATITUDE=67.4
IGARKA_LONGITUDE=86.6
IGARKA_NAME=Игарка
```

**Как получить токены:**

**Telegram Bot Token:**
- Найдите [@BotFather](https://t.me/BotFather) в Telegram
- Отправьте команду `/newbot`
- Следуйте инструкциям и получите токен

**Weather API Key (OpenWeatherMap):**
- Зарегистрируйтесь на [OpenWeatherMap](https://openweathermap.org/api)
- Перейдите в раздел API Keys
- Создайте бесплатный API ключ (Free tier)
- Скопируйте ключ в `.env`

### 4. Запуск бота

```bash
python -m app.main
```

После запуска вы увидите в консоли:
```
INFO - Бот запущен
```

Теперь бот готов к работе! Отправьте ему `/start` в Telegram.

## 🌐 Прокси для Telegram API (Shadowsocks)

### Зачем это нужно?

Если бот работает на сервере в России или другой стране с блокировкой Telegram API, трафик нужно пропустить через прокси за пределами блокирующей юрисдикции.

**Архитектура:**
```
контейнер bot → контейнер sslocal (SOCKS5) → зарубежный ssserver → api.telegram.org
```

### Настройка

#### 1. Зарубежный VPS с Shadowsocks Server

Убедитесь, что на зарубежном VPS уже установлен и работает `ssserver`:

```bash
# На VPS с ssserver
ssserver -s 0.0.0.0 -p 8388 -k your_password -m 2022-blake3-aes-256-gcm
```

Сохраните:
- **IP адрес VPS** (например, `203.0.113.42`)
- **Порт** (например, `8388`)
- **Пароль** (в base64 для методов 2022-*)
- **Метод шифрования** (например, `2022-blake3-aes-256-gcm`)

#### 2. Настройка .env на сервере в России

Скопируйте `.env.example` в `.env` и заполните переменные Shadowsocks:

```bash
# Shadowsocks proxy configuration
SS_SERVER=203.0.113.42                          # IP вашего зарубежного VPS
SS_PORT=8388                                     # Порт ssserver
SS_PASSWORD=your_password_base64                 # Пароль в base64
SS_METHOD=2022-blake3-aes-256-gcm               # Метод шифрования

PROXY_URL=socks5://sslocal:1080                 # URL прокси для бота
```

#### 3. Запуск с прокси

```bash
# Сборка и запуск с прокси
docker-compose build
docker-compose up -d
```

Docker Compose автоматически:
- Запустит контейнер `sslocal` с параметрами из переменных окружения
- Запустит контейнер `bot` с зависимостью от `sslocal`
- Пробросит трафик бота через SOCKS5 прокси

### Проверка работы прокси

#### 1. Проверка логов sslocal

```bash
docker-compose logs sslocal
```

Вы должны увидеть:
```
[INFO] listening on 0.0.0.0:1080
```

#### 2. Проверка логов бота

```bash
docker-compose logs bot
```

Вы должны увидеть:
```
✓ Прокси включен: socks5://***
✅ Успешное подключение к Telegram API
```

#### 3. Тест прокси внутри контейнера бота

```bash
docker-compose exec bot python -c "
import httpx
async def test():
    async with httpx.AsyncClient(proxy='socks5://sslocal:1080') as client:
        resp = await client.get('https://api.telegram.org/botXXX/getMe')
        print('Статус:', resp.status_code)
        print('Ответ:', resp.json())
import asyncio
asyncio.run(test())
"
```

### Отключение прокси

Если прокси больше не нужен:

```bash
# Удалите переменную PROXY_URL из .env

```

### Замечания безопасности

- ❌ **Не коммитьте** реальные значения `SS_PASSWORD` и IP адреса VPS в Git

### Расположение файлов в Docker

**Внутри контейнера:**
- Код приложения: `/app/app/`
- База данных: `/app/data/bot.db`
- Файл переменных окружения: `/app/.env` (монтируется только для чтения)
- Рабочая директория: `/app/`

**На хосте (вне контейнера):**
- База данных: `./data/bot.db` (монтируется как volume, доступна с хоста)
- Файл переменных окружения: `./.env` (монтируется как volume только для чтения, доступен с хоста)

**Важно:**
- Папка `data/` монтируется как volume, поэтому все изменения БД сохраняются на хосте
- Файл `.env` монтируется только для чтения (`:ro`), чтобы предотвратить случайное изменение из контейнера
- Переменные окружения загружаются через `env_file` в docker-compose.yml
- Логи выводятся в stdout/stderr и доступны через `docker logs`

## 📚 Описание сервисов

### 💰 salary_service.py
Сервис для расчёта зарплаты по вахтовому методу работы.

**Основные функции:**
- `calculate_salary()` - рассчитывает зарплату с учётом всех факторов
- `format_salary_report()` - форматирует отчёт для пользователя

**Учитываемые факторы:**
- Часовая ставка и отработанные дни
- Ночные смены (доплата 40%)
- Дни простоя (оплата 2/3 от ставки)
- Дни в пути (8 часов в день)
- Праздничные дни
- Премия месячная (33%)
- Региональная надбавка (0-100%)
- Северная надбавка (0-100%)
- Налог 13% (с учётом льгот)

### 🎁 annual_bonus_service.py
Сервис для расчёта 13-й зарплаты (годового вознаграждения).

**Основные функции:**
- `calculate_annual_bonus()` - рассчитывает годовую премию
- `format_annual_bonus_report()` - форматирует отчёт для пользователя

**Особенности расчёта:**
- Учёт дней работы по каждому месяцу года
- Среднемесячная база для расчёта
- Целевой процент годового вознаграждения по должности
- Коэффициенты KPI и корректирующие коэффициенты
- Региональные и северные надбавки на годовую премию
- Налог 13%

### 🌤️ weather_service.py
Сервис для получения текущей погоды для Ванкорского месторождения.

**Основные функции:**
- `get_weather()` - получает актуальную погоду через OpenWeatherMap API
- `format_weather_report()` - форматирует отчёт с эмодзи и датой

**Особенности:**
- Кэширование на 30 минут
- Отображение температуры, влажности, давления, ветра, видимости
- Форматирование даты на русском языке
- Учёт часового пояса UTC+7

### 📅 seven_day_weather.py
Сервис для получения прогноза погоды на 7 дней.

**Основные функции:**
- `get_7_day_forecast()` - получает прогноз на 7 дней
- `format_7_day_forecast_report()` - форматирует отчёт по дням

**Особенности:**
- Использует OpenWeatherMap API `/forecast` endpoint
- Группирует прогнозы по дням (из данных каждые 3 часа)
- Показывает минимум, максимум и среднюю температуру
- Отображает "Сегодня" и "Завтра" для первых дней
- Кэширование на 60 минут

### 🚁 flight_forecast_weather.py
Сервис для анализа вероятности вылета вертолёта на основе прогноза погоды.

**Основные функции:**
- `get_flight_forecast()` - получает прогноз для анализа вылета
- `format_flight_forecast_report()` - форматирует анализ с рекомендациями

**Анализ погодных условий:**
- Получает прогноз на 3 дня для Ванкора и Игарки
- Анализирует ветер, облачность, осадки, температуру
- Вычисляет баллы риска по специальным правилам для Крайнего Севера

**Система баллов риска:**
- Ветер > 12 м/с → +3 балла
- Порывы > 15 м/с → +3 балла
- Облачность ≥ 80% → +2 балла
- Осадки (снег/сильный дождь) → +2 балла
- Температура ≤ -45°C → +3 балла (экстремальный холод для Крайнего Севера)

**Рекомендации:**
- ≤ 3 балла: ✅ Вылет возможен
- 4-6 баллов: ⚠️ Осторожно — шанс задержки
- ≥ 7 баллов: ❌ Вылет НЕ рекомендуется

- Адаптировано для условий Крайнего Севера
- Юмористические комментарии для каждого дня
- Детальный анализ погодных условий для обеих точек маршрута
